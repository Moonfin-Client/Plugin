Web Client

How Moonfin in the browser finds and connects to this server.

Connecting to this server

Pre-fills the Add Server dialog in Moonfin web. Leave empty to auto-fill from the current Emby origin. Use the Emby base URL (for example, http://192.168.1.10:8096), not /web.
Forces Moonfin web to auto-connect to this URL on load. Leave empty to use plugin-mode auto-connect behavior. Use the Emby base URL and do not include a /web suffix.
Allows Moonfin web to scan private LAN ranges via WebRTC hints. Disable if your browser environment blocks or restricts WebRTC.

Seerr Integration

Enable Seerr integration for all users. Moonfin handles authentication through a server-side proxy so users can sign in once and stay authenticated across clients.
Where Emby can reach your Seerr server. Start the address with http:// or https://. Examples:
  • http://192.168.1.10:5055 (another machine on your network)
  • http://seerr:5055 (Docker, on the same network as Emby)
  • https://requests.example.com (a public address)
This is the address the Emby server connects to behind the scenes, not the one you open in a web browser, so a local network or Docker address works fine. You do not enter a username, password, or API key here; people sign in later from the app.

Advanced: If a reverse proxy in front of Seerr shows its own login page, let the Emby server through it. If Emby itself sits behind a reverse proxy, make sure that proxy forwards /Moonfin/ requests to Emby.
Optional override. The name shown in the UI (e.g., "Requests", "Media Requests"). Leave blank to auto-detect from the configured URL. The icon is always auto-detected regardless of this setting.
The address Seerr uses to reach this Emby server for request notifications (the webhook Seerr calls back). Set this when Seerr and Emby run in separate containers or hosts, since the server otherwise can only guess a local address that Seerr may not be able to reach. Use the base URL, for example http://192.168.1.10:8096 or https://emby.example.com.
SSO Proxy: When Seerr is enabled, Moonfin provides single sign-on. Users authenticate once with their Emby credentials, and the session is stored server-side. All Moonfin clients access Seerr API through /Moonfin/Seerr/Api/ without re-authenticating.

MDBList Integration

Provide a server-wide MDBList API key that all users can use for ratings (IMDb, Rotten Tomatoes, Metacritic, etc.). Users who set their own key in their Moonfin client settings will use that instead. This key also powers the MDBList official list home rows (IMDb Top 250, Most Popular, and similar charts), which the "Moonfin MDBList Official Lists Sync" scheduled task fetches and caches on the server.
Drops every cached rating so they refetch from MDBList. Use this if ratings look wrong or are missing after changing the key or updating the plugin.
Nightly task that caches MDBList's official charts (e.g. IMDb Top 250) so clients can show them as home rows without their own key.
Cap on items cached per official list (default 250).
Fetches IMDb charts (Top 250 movies/TV, Most Popular, and similar) on a schedule so clients can show them as home rows and custom rows can resolve the IMDb source. No API key required.

TMDB Integration

Provide a server-wide TMDB API key that all users can use for episode ratings, the seasonal Home row, and the parental ratings of titles in the IMDb, TMDB and MDBList rows. Users who set their own key in their Moonfin client settings will use that instead. Supports both v3 API keys and v4 Bearer tokens. This key is also used to fetch posters for the MDBList official list home rows. Without it, those rows still work but show titles without artwork.
Pre-warms the studio (production company) logo cache from TMDB on a schedule so clients can show studio logos on the details screen. Uses the server-wide TMDB key above.
Logos older than this are re-fetched (default 30).

Push Notifications (Optional)

Optional. Paste a Firebase service-account JSON to send Seerr push notifications directly through FCM from this server. Leave empty to use the hosted Moonfin push relay instead. Secret: never logged.
Optional path to a service-account JSON file on the server. When both this and the JSON above are set, the file path wins.
Where push notifications are forwarded when no service account is set. Leave blank to use the hosted Moonfin relay.
Overrides the key this build ships with, for anyone running their own relay. Secret: never logged.

Anime Filler & Recap Markers

Nightly task that matches your anime against AnimeFillerList so Moonfin clients can badge filler episodes. No account or API key is needed. Series are matched by title, falling back to the English and romaji titles behind their ids for libraries in other languages, and only shows the site actually lists are fetched.
Leave everything unchecked to consider every library. Matching is a local title lookup, so narrowing this only helps if a non-anime show shares a title with an anime.
Affects the Subbed/Dubbed pills. Normally an item also has to look like anime on its own, meaning it carries an AniList, AniDB, AniSearch, Kitsu or MyAnimeList id, or an "Anime" genre or tag. That check is what keeps a library holding both anime and ordinary shows from marking the ordinary ones.

If the libraries you picked above are only anime, turn this on: the check then only costs you the entries whose metadata happens to be thin, which would otherwise show no pill at all. Has no effect while no libraries are selected, since there is then nothing to trust.
AnimeFillerList has no recap category, so this asks MyAnimeList as well. It is best-effort and additive: if that lookup fails, the filler data is unaffected.
Reads the audio tracks in each file: Japanese and nothing else is Subbed, anything carrying another spoken language is Dubbed. A season gets a pill only when every episode in it agrees. This needs no internet and does not depend on AnimeFillerList, so it works for anime the site has never listed. Files whose audio has no language tag are left unmarked rather than guessed at.

In a mixed library: when you select your anime libraries above, only shows in them are marked. If you leave the selection empty the whole server is in scope, and a series is then only marked when it looks like anime on its own, meaning it carries an AniList, AniDB, AniSearch, Kitsu or MyAnimeList id, or an "Anime" genre or tag. A Japanese live-action show carrying one of those would still be marked.
Extends the same audio rules to movies, so the pill shows on a movie card anywhere it appears, including home screen rows. Separate from the option above because a movie has no series to inherit from, and a mixed library is most likely to mislabel a film.
A file holding the Japanese audio and a dub can be watched either way, so it shows as Subbed/Dubbed rather than just Dubbed. Leave off for the shorter label.
Full wording is longer while on Phones and Tablets a shorter label fits better.
Applies to episode rows in Moonfin clients. Season and movie cards always draw the pill over the artwork, since they have no runtime line to sit next to.
A pill that is switched off is never sent to a client, so every Moonfin client agrees. The two canon options are off by default: nearly every episode of most shows is canon, so turning them on puts a pill on almost everything.
Shows older than this are re-fetched (default 30). A finished show's classifications never change, so this mainly governs how quickly an airing show picks up new episodes.
Markers appear after the Moonfin Anime Markers Sync task has run. You can start it now from Scheduled Tasks in the Emby dashboard.
Type a series name from your library and press Preview to see exactly which of your episodes each marker landed on. Fetch now pulls that one show immediately (about ten seconds, the site's crawl delay) instead of waiting for the task.
Records every marker request a client makes and what it was answered with, to moonfin-anime-markers.log in the server's own log folder, so it also shows up under Logs in the Emby dashboard where it can be downloaded. Turn this on when a badge is not appearing: if a request never shows up here, the app never asked, which means the problem is in the app rather than on the server. Leave it off otherwise. 

                        

                    


                    

                    

                    

                        
Retro Games (EmulatorJS)

                        

                            
                            

                                Lets Moonfin clients browse and play ROMs from a "Mixed Content" library using
                                EmulatorJS.
                                Organize ROMs as System/<game>/rom.ext with any BIOS files at the
                                top of each system folder. No setup is needed for the emulator itself: cores stream
                                from the EmulatorJS CDN by default.
                            

                        

                        

                            
                            

                                Online (default): cores stream from the EmulatorJS CDN. Zero setup,
                                but each client needs internet access when a game launches.

                                Offline (self-host): install the cores on this server once so clients
                                play with no internet and lower latency. Use either option below; clients switch to
                                the local copy automatically once it is installed.
                            

                            

                                Checking...
                            

                        

                        

                            
                            

                                
                                
                            

                            

                                Upload an EmulatorJS data folder zipped up (the zip must contain
                                loader.js somewhere inside). Get it from
                                EmulatorJS releases
                                (extract the archive and zip its data folder). ~290 MB.
                            

                        

                        

                            
                            

                            

                                Select the libraries that hold your game ROMs, then click Save below. If none are
                                selected, libraries whose name contains "game", "rom", or "emulat" are auto-detected.
                            

                        

                        

                            
                            
                            

                                Play the games on a RomM server through one
                                of your libraries. Emby talks to RomM for the apps, so RomM only has to be reachable from
                                this server, and the RomM token never leaves it. Leave this empty to turn RomM off.
                            

                        

                        

                            
                            
                            

                                Create one in RomM's web interface under your profile's client tokens, with the
                                roms.read, platforms.read and firmware.read scopes.
                            

                        

                        

                            
                            
                            

                                The library whose games come from RomM instead of its folders. Any library works, so you
                                can add a Mixed Content library pointed at an empty folder just for RomM. Emby's library
                                access settings decide who sees it.
                            

                        

                        

                            

                                
                                
                            

                        

                        

                            Box art is fetched automatically from the keyless
                            libretro thumbnail server
                            (matched by game name); no API keys or accounts are needed.
                        

                    


                    

                    

                    

                        
Default User Settings

                        

                            Configure default Moonfin settings for all users. New users and users who haven't customized
                            a setting will see these values. Users can always override defaults in their own Moonfin settings panel.
                        


                        

                            How it works: These are the lowest-priority fallback. Resolution order:
                            User's device profile → User's global settings → These admin defaults → Built-in defaults.
                        


                        

                            Important: New nullable settings use Not set / Yes / No style inputs.
                            Not set means "do not force this value" so users keep their own choice.

PINs

                        

                            A PIN kept here applies on every device, so a PIN set once holds on each new TV. An app
                            that supports it asks for the PIN from this server and falls back to the PIN stored on the
                            device otherwise. A PIN is exactly four digits. After too many wrong guesses the server makes
                            the user wait. Setting a PIN here replaces any existing one, so it also resets a forgotten PIN.

Broadcast Message

                        

                            Send a message to all connected Moonfin clients right now. It is also saved to
                            the Messages tab, so users who were offline still see it later.
                            For anything you want to write properly, use the Messages tab instead.

Diagnostics

                        

                            
                            

                                Lets Moonfin clients send diagnostic and crash reports to this server, where they
                                appear under Logs as upload_<client>_<version>_<time>.txt.
                                This is what makes the app's "Send report to server" button work. Reports have
                                server addresses, IP addresses and access tokens stripped out before they leave
                                the device, and each user can upload 10 an hour, up to 1 MB each.
